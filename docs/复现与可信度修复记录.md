# 复现与可信度修复记录

## 1. 本轮修复目标

根据项目评审意见，本轮优先修复影响实验可信度和工程复现性的几个问题：

- 风险阈值不应由测试集自身计算。
- 交互式风险曲线不应因缩放窗口而改变风险判定标准。
- 深度模型训练需要固定随机种子。
- 测试脚本需要避开当前全局 Python 环境中的 pytest 插件冲突。

## 2. 风险阈值修复

原逻辑：

- 使用 `test` 集预测值和误差分布计算 warning/danger 分位阈值。
- 这会导致测试集告警评估偏乐观。

新逻辑：

- 使用 `validation` 集计算阈值。
- 将固定阈值应用到 `test` 集。
- 风险表中新增：
  - `threshold_source`
  - `evaluated_split`

当前结果：

- `threshold_source = val`
- `evaluated_split = test`

- [run_risk_warning.py](C:/Users/lenovo/Desktop/人工智能大赛/scripts/run_risk_warning.py)

## 3. 交互式风险曲线修复

原逻辑：

- 在当前展示窗口内重新计算分位数阈值。
- 用户改变时间范围后，同一个点可能被重新判定为不同风险等级。

新逻辑：

- 交互式风险曲线读取风险表中的固定阈值。
- 页面缩放和时间窗口选择只改变可视范围，不改变风险判定标准。

## 5. 测试脚本修复

当前全局 Python 环境中存在第三方 pytest 插件依赖冲突，直接运行：

```bash
python -m pytest -q
```

可能失败。

新增安全测试入口：

```bash
python scripts/run_tests.py
```

该脚本会设置：

```text
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
```

避免加载无关全局 pytest 插件。

本轮验证结果：

```text
1 passed
```
