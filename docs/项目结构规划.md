# 项目结构规划

## 1. 规划目标

为了便于团队协作、模型迭代、平台集成和比赛材料整理，建议项目从一开始就采用统一的目录结构。该结构需要同时支持以下几类工作：

- 数据集存储与预处理
- 实验脚本与模型训练
- 可视化平台开发
- 文档、申报书和答辩材料整理
- 结果输出与版本留存

## 3. 各目录作用说明

### 3.1 `data/`

用于存放所有数据文件，建议分层管理：

- `raw/`：原始数据，不直接修改
- `processed/`：清洗、特征构建后的训练数据
- `external/`：外部补充数据、论文附录数据、对比数据

建议将当前 SRU 数据集逐步迁移到：

```text
data/raw/sru/
```

这样后续如果加入新的预处理版本，也不会和原始数据混在一起。

### 3.2 `docs/`

用于存放比赛相关文档：

- `proposal/`：申报书、立项书
- `report/`：中期报告、技术报告、实验总结
- `ppt/`：答辩 PPT 文稿、讲稿提纲
- `references/`：参考文献、论文摘要、GitHub 调研记录
- `assets/`：文档图片、流程图、截图

### 3.3 `notebooks/`

用于快速探索和实验验证，适合：

- 数据分布可视化
- 特征相关性分析
- baseline 快速试验
- 图表导出

注意：`notebooks/` 更适合探索，不建议把正式训练逻辑长期留在 notebook 中。

### 3.4 `src/`

这是项目的核心代码目录，建议按职责拆分：

- `config/`：统一管理路径、参数和超参数
- `data/`：负责加载、清洗、切分和特征构造
- `models/`：负责模型定义
- `training/`：负责训练、评估和预测流程
- `analysis/`：负责解释分析、滞后分析和诊断逻辑
- `visualization/`：负责图表和汇报输出
- `app/`：负责监测平台和前端页面
- `utils/`：放公共函数

### 3.5 `scripts/`

用于放一键运行脚本，方便团队成员快速执行：

- 数据检查
- 数据预处理
- 模型训练
- 模型评估
- 平台启动

相比直接在 `src/` 里到处找文件，这种方式更适合协作和答辩前统一复现实验。

### 3.6 `outputs/`

用于存放项目运行结果，建议固定输出位置：

- `figures/`：曲线图、热力图、结构图
- `tables/`：实验结果表格
- `models/`：保存训练好的模型权重
- `logs/`：训练日志和运行日志
- `submissions/`：比赛提交材料、导出附件

### 3.7 `tests/`

即使比赛项目不要求完整工程化，也建议保留最基本测试：

- 数据能否正常读入
- 指标函数是否正确
- 推理接口是否能正常返回结果

## 4. 推荐开发顺序

建议按以下顺序启动项目：

1. 先搭好 `data/`、`src/`、`scripts/`、`outputs/` 的基础骨架。
2. 先完成 `data loader + preprocess + baseline train` 三个核心模块。
3. 再补 `analysis/` 中的延迟分析和可解释分析。
4. 最后接入 `app/` 做可视化平台展示。

## 5. 针对你们项目的最小可行结构

如果想先快速开工，不必一次建太复杂，可以先最小化为：

```text
人工智能大赛/
├─ data/
│  ├─ raw/
│  └─ processed/
├─ docs/
├─ notebooks/
├─ src/
│  ├─ data/
│  ├─ models/
│  ├─ training/
│  ├─ analysis/
│  └─ app/
├─ scripts/
├─ outputs/
├─ requirements.txt
└─ README.md
```

这个结构已经足够支持前期建模、中期迭代和后期答辩展示。

## 6. 当前阶段建议

结合你们目前的进度，建议下一步先做三件事：

1. 把现有 SRU 数据整理到 `data/raw/sru/`
2. 建立 `src/data/` 和 `src/training/`，先把 baseline 跑起来
3. 建一个 `scripts/run_train_baseline.py`，保证团队成员都能复现实验

## 7. 后续可继续扩展的内容

后面如果项目做得更完整，还可以继续加入：

- `deploy/`：部署脚本
- `api/`：后端接口
- `configs/`：YAML 配置文件
- `experiments/`：实验记录和参数管理
- `models/checkpoints/`：细粒度模型版本管理
